# ADR-0011: 테넌트 폭주 격리 — 테넌트별 구독(세션·큐) 분리

- 상태: **채택, 구현 미착수** (2026-10-25). 방향은 사용자 결정(선택지 B)이다. 구현은 Phase 6 이후로 미뤘고 TC-17 은 그때까지 "미달"이다.
- 관련: TC-17, TC-06, ADR-0001, ADR-0004, ADR-0007, 불변식 4·5, [phase6-tc17.md](../experiments/phase6-tc17.md)

## 배경

한 테넌트의 폭주가 브로커의 `max_queued_messages`(60,000)를 넘기면 이미 PUBACK 한 메시지가 사라지고,
세션이 하나라서 평온한 테넌트의 메시지도 같이 사라질 수 있다(150,000건 폭주에서 2.6% 유실, 평온한 테넌트 유실 1회 관측).

## 선택지

| | 내용 | 판단 |
| --- | --- | --- |
| A | 테넌트별 발행 한도 | Mosquitto 기본 기능으로는 어렵다 |
| **B** | **테넌트별 topic 접두어 + 테넌트별 구독 세션(큐)** | **채택.** 큐가 격리돼 피해가 폭주 테넌트에 한정된다 |
| C | 큐 상향 + 큐 깊이 경보 | 격리가 안 된다 |

## 결정

테넌트마다 별도 MQTT 세션(client id, 구독 topic)과 별도 브로커 큐를 갖는다. 폭주 테넌트의 큐가 넘쳐도 다른 테넌트의 큐는 영향을 받지 않는다.

## 구현할 때 다시 결정해야 하는 것 (미결)

구현 전에 선택지를 제시하고 사용자에게 묻는다.

1. **저장 워커 구성:** 불변식 5(저장 워커 단일 고루틴, ack 순서 = 수신 순서)와 충돌한다. 테넌트별 세션·채널은 두되 워커를 하나로 유지할지(공정성 정책 필요), 테넌트별 워커로 바꿀지(불변식 5 수정).
2. **topic 구조:** 현재 `sensors/+/+`. 테넌트 접두어를 넣으면 에뮬레이터와 센서 펌웨어, ACL, 센서→테넌트 매핑이 바뀐다.
3. **테넌트 추가·삭제 시 세션 관리:** 동적 구독, 영구 종료 시 큐 정리(ADR-0007 의 운영 절차 확장).
4. **리소스 상한:** 테넌트 수 × 큐 크기 × 채널 크기가 불변식 4(메모리 상한)를 지키는지.
5. **`max_queued_messages` 와 브로커 전체 메모리:** 테넌트별 상한 설정 방식(Mosquitto 는 전역 설정이다).
6. 통과 기준: TC-17 을 폭주 150,000건 조건으로 재시험해 다른 테넌트 유실 0.

## 영향

- TC-17 은 구현 전까지 미달이다. README 에 그대로 표시한다.
- TC-06(5분 조건)과 큐 깊이 사전 경보는 이 결정과 별개로 남는다.
