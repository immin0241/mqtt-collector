# ADR-0002: 재시도와 백프레셔 정책

- 상태: 채택 (2026-10-23, 사용자 결정 B)
- 관련: 불변식 2, 4, TC-02, TC-06

## 선택지

| | 설명 | 장단점 |
| --- | --- | --- |
| **a (채택)** | 일시적 오류는 성공할 때까지 지수 백오프로 재시도. 그동안 채널이 차면 수신 핸들러가 막힌다. | 데이터를 버리지 않는다. 장애가 길면 수신이 정지하고 브로커 큐가 쌓인다. |
| b | 최대 시도 후 격리하거나 프로세스를 중단 | 정지는 피하나 정상 데이터를 격리하거나 재시작 루프가 생긴다. |

## 결정

- 백오프: 초기 500ms, 두 배씩 증가, 상한 30s (`workers/db_push_worker.go`의 `defaultRetry*`).
- 재시도는 `DbPushWorker` 고루틴 안에서 수행한다. 이 동안 채널을 소비하지 못해 채널(600) → 수신 핸들러 → paho 읽기 루프 순으로 막힌다.
- 메모리 상한: 채널 600 + 배치 300 + paho/브로커 측 inflight. 모두 고정 상한이다.
- 종료 신호가 오면 재시도를 중단하고, 종료 절차의 최종 flush(`ShutdownTimeout` 10s)를 한 번 더 시도한다. 실패하면 ack하지 않아 브로커가 재전달한다.

## 결과 / 위험

- 핸들러가 막힌 동안 keepalive(60s)와 ping timeout(5s)을 넘기면 연결이 끊길 수 있다. 재연결 후 미ack 메시지가 재전달되므로 유실은 아니지만, TC-02(DB 10초)와 TC-06에서 실제로 확인한다.
- 무한 재시도이므로 영구 장애(권한 오류 등)는 수신 정지로 나타난다. Phase 2의 `db_errors_total{kind}`와 `last_flush_timestamp`로 감지한다.
